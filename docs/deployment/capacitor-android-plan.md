---

## 1. Decision

Capacitor is the fit for this codebase because:

1. Frontend is a standard CRA SPA with centralized API config (`frontend/src/config.js` → `REACT_APP_API_URL`) — it can run inside a native WebView with no rewrite.
2. Backend is already API-only (JWT, HTTPS) — mobile is just another API client.
3. The voice-input roadmap needs a real mic permission (`RECORD_AUDIO`); Capacitor provides it via a speech-recognition plugin, whereas PWA mic on Android WebView is unreliable.
4. One codebase ships web (Vercel) + Android (Play `aab`).

Out of scope: iOS, React Native rewrite, offline-first sync.

---

## 2. What stays / what changes

| Layer | Change |
|-------|--------|
| Backend code | None. `POST /api/expenses`, `POST /api/voice-expenses/draft`, auth middleware all reused as-is |
| Backend env | Extend `CORS_ALLOWED_ORIGINS` with `http://localhost`, `https://localhost`, `capacitor://localhost`, plus laptop LAN origin for device testing |
| Frontend code | Minimal: `homepage` relative paths, router check, speech-recognition plugin branch, token storage migration (later) |
| New native shell | `frontend/android/` generated by Capacitor (do not hand-edit except permissions/icons) |
| API URL | Build-time `REACT_APP_API_URL`: LAN IP for device test, production Render URL for release |

## 3. Pre-`cap init` file changes

| # | File | Change |
|---|------|--------|
| 1 | `frontend/package.json` | `"homepage": "/"` → `"homepage": "./"` (relative asset paths for `capacitor://localhost`) |
| 2 | `frontend/.env` (device test) | `REACT_APP_API_URL=http://<LAPTOP_LAN_IP>:5000/api` (physical phone; `localhost` on phone ≠ laptop). Rebuild after every URL change |
| 3 | `backend/.env` | Add `http://localhost`, `capacitor://localhost`, `http://<LAN_IP>:3000` to `CORS_ALLOWED_ORIGINS`. Keep `NODE_ENV=development` for local test (allows all origins) |
| 4 | `frontend/src/index.js` | Verify `BrowserRouter` on device; fall back to `HashRouter` if deep-link refresh 404s in WebView |
| 5 | `frontend/src/components/VoiceExpenseInput.jsx` | Add native branch: if `window.SpeechRecognition` missing, use `@capacitor-community/speech-recognition` (permission flow + `RECORD_AUDIO`) |

Known web-API gaps: `localStorage`/`sessionStorage` auth + theme + lang work in WebView but `sessionStorage` is ephemeral — migrate tokens to `@capacitor/preferences` after first device test. Admin token (session-only) first.

## 4. Install & sync commands (repo-specific)

```bash
# 0. Backend running on LAN; frontend built with LAN API URL
cd ~/Documents/Projects/ExpenseTracker/backend && npm run dev
cd ~/Documents/Projects/ExpenseTracker/frontend && npm run build

# 1. Capacitor core (web-dir is frontend-relative)
cd ~/Documents/Projects/ExpenseTracker/frontend
npm install @capacitor/core @capacitor/cli
npx cap init "Expense Tracker" com.shaminda.expensetracker --web-dir=build

# 2. Android + plugins required by this app
npm install @capacitor/android @capacitor/preferences
npm install @capacitor-community/speech-recognition
npx cap add android
npx cap sync

# 3. Iterate
npm run build && npx cap sync && npx cap open android
# Run ▶ in Android Studio on USB device (USB debugging ON, `adb devices` visible)
# LAN shortcut alternative: adb reverse tcp:5000 tcp:5000 (then localhost API URL works)
```

Android Studio is required at least for first setup (SDK + platform-tools + USB driver + signing). Daily runs can use `npx cap run android` afterwards.
