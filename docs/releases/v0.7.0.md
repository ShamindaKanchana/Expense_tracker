# Release v0.7.0

**Date:** 2026-09-14  
**Previous release:** [v0.6.0](./v0.6.0.md)

## Summary vs previous release

This release adds a trilingual voice expense workflow: users can speak an expense in English, Sinhala, or Tamil, review the transcript and structured draft, and explicitly confirm it before saving through the existing expense API. Extraction is provider-configurable and constrained to the app's canonical categories.

| Area | v0.6.0 | v0.7.0 |
|------|--------|--------|
| Expense entry | Manual form | **Manual form plus voice draft preview and confirmation** |
| Languages | Localized UI | **English, Sinhala, and Tamil voice recognition and extraction** |
| Extraction | N/A | **Structured amount, description, category, and date draft** |
| LLM integration | N/A | **Server-side configurable Cohere, Gemini, OpenAI-compatible, DeepSeek, and mock adapters** |

## Features

### Trilingual voice expense input

- Dashboard microphone action without changing manual expense entry
- Browser speech recognition in `en-LK`, `si-LK`, and `ta-LK`
- Transcript and extraction preview shown as a message-style panel; the manual form is not prefilled
- `Proceed` opens a final confirmation dialog; only `Confirm & save` writes the expense
- Retry, discard, permission-error, unsupported-browser, timeout, and success states
- Responsive desktop/mobile UI with localized English, Sinhala, and Tamil copy

### Structured, safe extraction

- New authenticated `POST /api/voice-expenses/draft` endpoint
- Provider-neutral, versioned system prompt with the trusted canonical category list
- Strict Zod validation for nullable `amount`, `description`, `category`, and `date` fields
- Deterministic date, amount, range, length, and category validation before preview
- Existing `POST /api/expenses` payload and database contract preserved

### Configurable LLM providers

- Runtime provider selection through environment variables
- Cohere, Gemini, OpenAI-compatible, and DeepSeek adapters
- Development-only deterministic mock provider; production rejects mock mode
- Bounded timeout/retry handling and safe provider error responses

## Bug fixes / UX

- Canonical category validation now protects both manual and voice expense writes
- Dashboard data refreshes after a confirmed voice save
- Escape key dismisses an active voice panel or confirmation state

## Deployment / upgrade notes

- Set `LLM_PROVIDER`, `LLM_MODEL`, and the matching server-side provider key on the backend.
- Set `VOICE_ALLOW_MOCK=false` in production; never expose provider keys to the frontend.
- Set `CORS_ALLOWED_ORIGINS` to the deployed frontend origin.
- Set frontend `REACT_APP_API_URL` to the deployed backend `/api` base URL and rebuild.
- Browser speech recognition requires a supported browser and HTTPS outside localhost; no separate STT key is used in this first slice.
- No database migration is required for voice drafts.
